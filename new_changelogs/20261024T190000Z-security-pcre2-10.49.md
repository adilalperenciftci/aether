- **The vendored PCRE2 is 10.49, up from 10.44.** It is what `std.regex` runs
  on a box without a system libpcre2-8, and in every `ae build --target` cross
  build. Of the fixes since 10.44, the one std.regex can reach is
  GHSA-fmgr-6ggq-9859: integer overflows while compiling a pattern on 32-bit
  CPUs, leading to out-of-bounds writes. The rest (GHSA-r9hj-j2rw-4q3m,
  -2p8c-ff85-vh9x, -3r4p-g7gg-ppmf, -9qww-pwc4-77qq, -q8g2-wprr-34m9,
  -q7rw-r7qq-2hx6) are in JIT, DFA, invalid-UTF, convert and serialize paths
  std.regex does not call. Patterns see PCRE2's own changes since 10.44:
  Unicode 17, `\p{Ll}` / `\p{Lu}` / `[:lower:]` under caseless matching now
  match both cases as Perl does, and `\x` not followed by `{` or a hex digit is
  no longer a NUL escape (write `\x00`). The release tarball's GPG signature
  checks against the key upstream's SECURITY.md names. Builds that use a
  system libpcre2-8 are unchanged.
