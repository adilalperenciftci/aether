# x509-limbo cases std.cryptography.tls13_cert does not run (SKIP), does not
# agree with (FAIL), or agrees with where OpenSSL does not (AGREE, a note),
# one per line: <id> SKIP|FAIL|AGREE <reason>. limbo.ae fails the run on any
# other disagreement, and on a FAIL line whose case has come to agree. Every
# case not listed runs and agrees, the bettertls namespace included.
#
# The rule: std.http's two TLS backends accept the same chains, except where
# OpenSSL accepts something unsafe; there the pure backend refuses, and the
# OpenSSL backend is tightened wherever a flag allows it (#3312, #3313).
# "OpenSSL" below is `openssl verify` 3.6.4 set up as that backend verifies
# a server: purpose sslserver, the host or IP, no partial chains, plus the
# backend's own flags where the command has none (NO_PARTIAL_WILDCARDS,
# NEVER_CHECK_SUBJECT, security level 2).
#
# bettertls, where every case agrees with limbo, differs from OpenSSL on 183
# cases, none where the pure backend accepts what OpenSSL refuses for a
# reason that matters:
#   90 accepted here, refused by OpenSSL, which applies DNS name constraints
#      to the subject CN of a leaf with no DNS SAN; neither backend uses the
#      CN for names;
#   71 refused here, accepted by `openssl verify`, which matches the host
#      against the CN; the OpenSSL backend never does (#3313);
#   22 accepted here, refused by OpenSSL, which does not try the other path
#      that is valid.
