# x509-limbo cases std.cryptography.tls13_cert does not run (SKIP) or does
# not agree with (FAIL), one per line: <id> SKIP|FAIL <reason>.
# limbo.ae fails the run on any other disagreement, and on a FAIL line whose
# case has come to agree. Every case not listed runs and agrees, the
# bettertls namespace included (9572 of 9572).
#
# The FAIL lines are choices, not missing work: the validator enforces what
# changes which names and keys a path authorises, refuses certificates that
# are malformed or that use an extension where RFC 5280 forbids it, and does
# not enforce issuance-profile rules (the CA/Browser Forum's, RFC 5280's
# "conforming CAs MUST") that change nothing a path authorises. On every
# FAIL line, std.http's OpenSSL backend reaches the same verdict as this
# one (checked with `openssl verify` 3.6.4 set up as that backend verifies
# a server: purpose sslserver, the host or IP, no partial chains), because
# the backend a program runs on must not change which chains it accepts.
